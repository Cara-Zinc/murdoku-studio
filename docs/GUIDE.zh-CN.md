# Murdoku Studio 使用指南

[返回中文 README](../README.zh-CN.md) · [English README](../README.md)

## 人物编号与头像

编号按姓名首字母分配，例如 Angelo → A、Blake → B、Vivianna → V，不受 PDF 文字提取顺序影响。首字母重复时用 AA 等编号区分。已有案件可在「编辑案件 → 人物与规则」点击「按姓名修正编号」再保存；人物位置、候选笔记和规则引用会同步更新。

导入 PDF 时，程序优先选择较大的姓名标签，再查找姓名上方附近的矩形头像框。人物卡和棋盘中的已放置人物显示同一头像，并保留角落字母。

在「调整头像框」中，拖动蓝框移动，拖动四角缩放；方向键微调，Shift 加速。也可直接填写位置和尺寸百分比。「应用头像」只更新编辑草稿，还需点击「保存案件」。取消任一层编辑会丢弃该层未保存的更改。「清除头像」恢复编号显示。已有案件只要保留了原页，也能手动框选；重新导入 PDF 可运行自动匹配。

## 局部视野

大题默认使用侦探放大镜。蓝框表示主棋盘当前显示的范围，可在小地图上连续拖动，不固定切成九块。显示的 I9 等坐标始终对应全局棋盘。

平移、跳转和缩放不会改动人物位置或笔记。当前视野随页面保存；解谜的撤销和重做不撤销视野移动。「返回上一视野」只保留本次会话的导航记录。全屏模式也提供小地图。手机可开启「平移」后单指拖动主棋盘，或直接拖动小地图的观察框。

## 放置与排除

确认放置后，同一行、同一列的其他空格显示黑叉。「黑叉粗细」支持 1–8 px，设置保存在当前浏览器，也适用于手动排除。

自动黑叉由人物位置实时计算，不会删除原候选。移动人物或撤销后，自动排除随之更新，可用格子恢复原笔记。手动排除标记独立保存。重复点击同一人物的位置会将其移走。

## 规则模型

每人最多一个位置，每行和每列最多一人。标准方形题的人数等于边长。物品是否可占用由格子的 `blocked` 配置决定。“相邻”仅指同一区域的上下左右。完成布局后，受害者所在区域必须恰有一名同伴。

支持的规则包括区域/不在区域、行、列、物品上、相邻/不相邻、区域包含物品、与某人同区域/不同区域、独处、区域内另一人在物品上/旁边，以及允许的格子集合。同一人物的多条规则是“且”的关系。

例如，“所在区域有箱子，但不与箱子相邻”应配置为「区域包含：箱子」和「不相邻：箱子」。“所在区域有一名男性在床上”可用「另有人在物品上：床」，并限制另一人为男性。性别应依据原题填写，不能凭名字猜测。

原题中的复杂量词、视线、条件分支等未必能由现有规则完整表达。此时保持未核对状态，继续手动解谜。

求解器在 Worker 中运行，有时间和搜索节点限制。多解、无解、规则未核对或搜索未完成时，不会给出确定的正确位置。指认结果表示满足已配置规则，不代表与官方答案比对通过。

## 数据与备份

棋盘格式为 `version: 1`，包括 `rows`、`cols`、`cells`、`rooms` 和 `people`。内部位置使用从 0 开始的行优先索引，界面显示为 A1 等坐标。格式校验见 [engine.js](../murdoku-studio/public/engine.js)。

原始 PDF、页面图片、头像和进度保存在浏览器 IndexedDB。JSON 导出仅包含当前页的棋盘、图片、规则和进度；多页题需要逐页导出。编辑案件会清空当前页的撤销记录，保留仍然有效的人物位置和笔记。

## 手动验证流程

使用原创样本 `murdoku-studio/tests/fixtures/grid.pdf`：导入 → 校准 6×6 网格 → 转换 → 记录候选 → 放置/移动/撤销 → 等待保存完成 → 刷新 → 翻到第 2 页 → 返回第 1 页 → 导出并重新导入。再在 390px 宽视口检查工具和弹窗。
